# Palette descriptor loader at `0x8003D0CC`

The production C source matches the full 244-byte routine. It allocates one
40-byte descriptor per input record, using the count at input offset four.
The first header word is skipped without validation, as in retail.

The routine writes only mode (`+0x08`), palette count (`+0x14`), palette pointer
(`+0x18`), and palette byte size (`+0x1C`). The remaining descriptor fields are
left untouched. The adjacent image/texture loaders use the same descriptor
layout; the bounds-checked host palette decoder remains a separate tool.

Mode zero consumes a count followed by that many 32-byte palettes. Mode one
consumes a count followed by that many 512-byte palettes. These are the 16- and
256-colour BGR555 layouts. Mode two zeros the count and byte size without
assigning the palette pointer. Other mode values consume only their mode word.
A zero record count still calls the allocator and returns its result.

The cursor is a target `unsigned int *`: one cursor step is four bytes.
Pointer advances use eight or 128 words per palette, while the stored sizes
use 32 or 512 bytes. Empty constraints retain these two extent calculations
and keep the count store before its register copy. They add no instructions.
The size assertion requires the 40-byte PS1 descriptor layout, including its
32-bit pointer; this is not a native-host structure for decoding disc bytes.

The emitted section is 256 bytes, including 12 bytes of zero tail padding.
The verifier compares all 244 routine bytes and rejects nonzero tail bytes.
