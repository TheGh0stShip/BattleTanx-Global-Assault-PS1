# `func_8004CFFC` reconstruction notes

This routine gates vehicle path-target handling. The related N64 routine is
`func_80082870`; the PS1 version uses fixed-point vectors and a fixed distance
threshold of `0x1E000`. The production source is now
[`src/game/8004CFFC.c`](../../src/game/8004CFFC.c), with all 124 retail bytes
matching under the manifest's GCC 2.8.1 configuration.

Recovered behavior:

- a null target returns one without calling either helper
- a three-point path test result other than one returns one without calling
  the distance helper
- when the three-point test returns one, a signed distance of at most
  `0x1E000` returns one; a greater distance returns zero

Confirmed structure offsets:

- vehicle position: `+0x08`
- current path goal: `+0x13C`

The earlier candidate had incorrect early-return semantics. Direct disassembly
of the verified retail executable shows both the null-target branch at
`0x8004D018` and the failed path-test branch at `0x8004D034` targeting
`0x8004D058`, which assigns one to the result. They do not target the following
return-value copy at `0x8004D05C`. The distance-failure branch at `0x8004D050`
instead targets `0x8004D060`, after copying the initial zero into the return
register in its delay slot. This distinction corrects the earlier research.

Retail assigns the target to `s2`, the result to `s1`, and the position pointer
to `s0`. Register bindings, an empty target constraint, and an empty C loop
preserve those lifetimes and the retail prologue scheduling. The main single-pass
loop expresses the early branches to the shared assignment of one. Its distance
failure exits directly to the return. No instruction blobs are used.

The assembler emits 128 bytes: 124 exact routine bytes and four bytes of zero
section padding. The standalone candidate is a readable behavior reference;
the production source and manifest provide the exact build.
