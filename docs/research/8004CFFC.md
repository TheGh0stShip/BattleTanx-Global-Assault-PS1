# `func_8004CFFC` reconstruction notes

This routine tests whether a vehicle has reached its active path target. The
corresponding N64 routine is `func_80082870`; the PS1 version uses fixed-point
vectors and a fixed distance threshold of `0x1E000`.

Recovered behavior:

- a null target returns zero
- the target must pass the three-point path test
- the distance helper must report at most `0x1E000`
- satisfying all conditions returns one; every other path returns zero

Confirmed structure offsets:

- vehicle position: `+0x08`
- current path goal: `+0x13C`

The candidate emits 128 bytes for the 124-byte retail extent, followed only by
zero padding. It differs in 22 of 31 instruction words. The calls, constants,
field offsets, comparison semantics, frame size, and return values are all
recovered.

The remaining mismatch is compiler shape. Retail assigns the target to `s2`,
the accumulated result to `s1`, and the position pointer to `s0`. Binding only
the target to `s2` obtains the correct value roles, but GCC schedules the
prologue differently and folds the final branch into an `xori`. Binding all
three registers restores the intended body roles but adds setup instructions.

This candidate is research-only and is not included in the exact-unit
manifest.
