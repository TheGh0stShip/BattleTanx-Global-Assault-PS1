# `func_8004CFB4` reconstruction notes

This routine returns the active path-node position only when the vehicle's
target-node identifier matches its current path-node identifier.

Recovered behavior:

- compare the unsigned 16-bit fields at `+0x148` and `+0xFC`
- return null when the identifiers differ
- otherwise resolve the current path node through `func_8004BE20`
- return null when resolution fails
- return the resolved node plus four bytes when resolution succeeds

The candidate reproduces 16 of the routine's 18 instruction words. The only
differences are the order of the independent `s0` and return-address stores in
the prologue. The body, branches, delay slots, field widths, offsets, call,
return paths, frame size, and epilogue all match retail.

The generated extent is 80 bytes because the linker rounds the 72-byte routine
up to its alignment; all eight padding bytes are zero. The retail extent is 72
bytes.

Source-shape tests included pointer and integer results, forced and ordinary
register variables, reordered field loads, explicit temporaries, ordering
constraints, and scheduling flags. Each correct 72-byte body retained the same
two-word prologue difference. Constraints that reversed the stores also moved
the zero initialization ahead of the retail location.

This candidate is research-only and is not included in the exact-unit
manifest.
