# Texture entry reader at `0x8003CB80`

The production source matches all 360 retail bytes. It reads the width, height,
and mode, records the pixel-data pointer, then advances the caller's cursor
through one texture entry. The descriptor is 40 bytes, with 32-bit target
pointers; its size is enforced at compile time.

Mode zero computes `(width / 2) * height`, using signed division toward zero.
Mode one computes `width * height`; mode two computes `width * (height << 1)`.
Pixel advances use the resulting size as an unsigned word count, flooring the
byte advance to a multiple of four. This is the retail rounding already
reported separately by the bounded host decoder.

For modes zero and one, magic `0x4C415033` (`3PAL`) selects an explicit palette
count from the stream. Other magic values use one palette. The palettes occupy
32 or 512 bytes each, respectively. The two count reads are retained as volatile
accesses to reproduce the separate word-advance and byte-size calculations.
The descriptor's count member itself remains an ordinary integer.

Mode two zeros the palette count and byte size, leaving its palette pointer
untouched. Unknown modes retain the existing pixel-size and palette fields.
The caller's cursor is stored before the final pixel-size check. A nonzero
pixel size invokes `func_8003CA54`, which builds and uploads the image and palette
objects; the reader adds no input validation absent from retail.

Empty constraints retain the copied mode value and register lifetimes across
the case blocks. No instruction blobs or instruction-emitting assembly are
used. The assembler emits 368 bytes: the 360-byte routine and eight bytes of
zero section padding, verified independently.
